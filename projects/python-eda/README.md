# Исследовательский анализ продаж на Python

**Ноутбук:** [eda.ipynb](eda.ipynb) (открывается прямо на GitHub)

**Задача.** Руководитель прислал выгрузку продаж за два года, склеенную из кабинетов Wildberries, Ozon и CRM сайта (43,8 тыс. строк), и спрашивает: «Что происходит с продажами и на что обратить внимание?»

**Что сделано:**
1. **Оценка качества данных:** нашёл строку «ИТОГО» из Excel, тестовый заказ, 648 дублей, два формата дат, цены строкой («3 228,00»), 6 неверных вариантов написания Москвы и Петербурга, «WB» вместо «Wildberries».
2. **Очистка с журналом шагов:** сколько строк было, стало и почему удалено.
3. **Сверка с эталоном:** после очистки число позиций и сумма совпадают до рубля.
4. **Исследование:** динамика по каналам, индекс сезонности, распределение чека, маржа и возвраты по категориям (тепловая карта), география, новые и повторные покупатели.
5. **Выводы для руководителя** таблицей «что видно → что значит → что сделать».

**Главные выводы:**
- Сайт вырос с 18% до 24% выручки; чек там выше за счёт числа товаров в заказе (2,6 против 2,0).
- Декабрь в 1,5 раза выше среднего месяца, дни недели почти не влияют: планировать нагрузку нужно по месяцам.
- Текстиль даёт 21% выручки и лидирует по возвратам: 14%, на WB — 17%.
- Доля выручки от повторных покупок с 2025 года не растёт (~40%): удержанием никто не занимается.

**Стек:** Python, pandas, NumPy, Matplotlib.

**Запуск:** `python data/generate.py`, затем открыть ноутбук в Jupyter или VS Code.

> Данные синтетические ([`data/generate.py`](../../data/generate.py)), грязь в выгрузке воспроизводит типичные проблемы реальных выгрузок.
